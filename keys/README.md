# Public test keys — deliberately public

Every private key in this directory is intentionally public. These fixtures are for experiments only. Never use them for production authentication.

| ID / kid | Algorithm | Files |
| --- | --- | --- |
| jwt-lab-rsa-a | RSA-2048 / RS256 | rsa-a-private.pem, rsa-a-public.pem, rsa-a-certificate.pem |
| jwt-lab-rsa-b | RSA-2048 / RS256 | rsa-b-private.pem, rsa-b-public.pem |
| jwt-lab-ec | P-256 / ES256 | ec-private.pem, ec-public.pem |

`jwks.json` contains only public parameters. `rsa-a-certificate.pem` is the matching RSA-A self-signed X.509 certificate for x5u tests, not an HTTPS server certificate.

Private PEM files use PKCS#8; public PEM files use SPKI. The browser imports identical material bundled in `src/keys.js`, without fetching keys during payload generation.

Default JKU references `keys/jwks.json` on the deployment host; x5u references `keys/rsa-a-certificate.pem`. Acceptance depends on the target incorrectly trusting these sources and is never guaranteed.

Keep PEM, bundled modules, JWKS, and certificate synchronized. Run `node --test` to check consistency. Keys generated by the local crypto tools are kept in page memory and are not published here.
